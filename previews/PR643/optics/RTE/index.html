RRTMGP.RTE.NoScatLWRTE — Type
NoScatLWRTE(grid_params::RRTMGPGridParams; params, sfc_emis, inc_flux,
            n_gauss_angles = 1)

A high-level RRTMGP data structure storing the optical properties, sources, boundary conditions and fluxes configurations for a non-scattering longwave simulation.

Fields

  • context: ClimaComms context.
  • op: Optical properties.
  • src: Longwave source functions.
  • bcs: Longwave boundary conditions.
  • fluxb: Temporary storage for bandwise calculations.
  • flux: Longwave fluxes.
  • angle_disc: Angular discretization; n_gauss_angles sets the number of Gauss-Jacobi-5 quadrature angles (1-4) used for the hemispheric integral of the spectral solve. One angle is the diffusivity approximation; more angles resolve the angular integral better, at proportional cost. Gray radiation is single-angle and rejects anything but 1.
  • state_cache: TransposedStateCache with column-first copies of the hot state arrays (refreshed at each spectral solve), or nothing.

G-point groups

A two-stream solve can spread its g-point loop across the threads of one wider kernel instead of running it on one thread per column. These hold the per-group workspaces that make that possible.

RRTMGP.RTE.LWGptGroups — Type
LWGptGroups(grid_params::RRTMGPGridParams, ngroups; params)

Workspaces for solving a column's longwave g-point loop in ngroups independent pieces, covered by one grid rather than by one column's serial loop.

At one thread per column the whole solve fits in a single wave of blocks, so nothing is queued behind it: a block that finishes early frees its multiprocessor to no one, and the launch lasts as long as its slowest column. Columns are not equally expensive – a column sweeps the cloudy increment only where its mask is set, and in the shortwave a night column exits at once (see SWGptGroups) – so that difference is paid in idle warps instead of being absorbed. Splitting the g-point loop multiplies the blocks, and the scheduler refills a multiprocessor as each retires.

Every workspace the solve indexes by column is widened to ncol * ngroups, so a thread's (column, group) pair selects its slice by one index and the kernel body is the ungrouped one with that index substituted wherever it touches scratch. Nothing is allocated or walked per group: the reduction recovers the group from the wide column index.

ngroups > 1 is implemented for CUDA. The CPU driver ignores these workspaces and solves the whole g-point loop per column, which is correct either way.

RRTMGP.RTE.SWGptGroups — Type
SWGptGroups(grid_params::RRTMGPGridParams, ngroups)

Workspaces for solving a column's shortwave g-point loop in ngroups independent pieces, covered by one grid rather than by one column's serial loop.

LWGptGroups carries the reasoning, which holds here unchanged.

Two things differ from the longwave. FluxSW carries a direct-beam profile, so a group accumulates three planes rather than two. And the shortwave sweeps only where the sun is up, so every group of a night column exits its loop at once, which is the imbalance more blocks than one wave can absorb.

RRTMGP.RTE.default_ngpt_groups — Function
default_ngpt_groups(grid_params::RRTMGPGridParams)

How many g-point groups RRTMGPSolver widens a two-stream solve to when the caller names none: enough to reach TARGET_GPT_GROUP_COLUMNS wide columns, capped at MAX_NGPT_GROUPS and at what a GPT_GROUP_MEMORY_DIVISORth of the device's memory affords on this grid's level count and float type, which gpt_group_bytes counts.

A column count that already fills the device gets one group, and so does a CPU, whose driver solves the whole g-point loop per column and ignores the workspaces. Both gates matter because the count rises as columns fall, so an ungated default would give the smallest runs the widest workspaces. Pass ngpt_groups to override in either direction – a device whose free memory is smaller than its share of its own total wants that rather than the default, since the bound is on the total.

Grouping changes the order in which a column's g-points are summed, and floating-point addition is not associative, so grouped fluxes differ from a serial solve at roundoff – about 1e-6 relative in the configurations tested – and the clear-sky half of a both-skies solve no longer equals a standalone clear-sky solve exactly. Pass ngpt_groups = 1 where bit-for-bit agreement is required. The cloud-cover tally is a count of g-points and stays exact. What grouping does to a sum is the whole of the difference: at one group the g-points are taken in the serial order, and the solve is then bit-for-bit with the serial one, which is what the tests assert.

RRTMGP.RTE.gpt_group_bytes — Function
gpt_group_bytes(FT, ncol, nlay, ngroups)

Device bytes LWGptGroups and SWGptGroups together commit for ngroups groups of ncol columns on nlay layers, which is the quantity default_ngpt_groups bounds. A coupled run builds both bands, so this prices both.

Each band adds a byte of cloud mask per level and, per wide column, a surface source and a cloudy tally. The optics and the mask are over layers rather than levels and are charged a level each, which keeps the count on the safe side of the bound; test/gpt_group_workspaces.jl holds it to exactly that.

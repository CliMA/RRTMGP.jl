RRTMGP.RTE.NoScatLWRTE — Type
NoScatLWRTE(grid_params::RRTMGPGridParams; params, sfc_emis, inc_flux,
            n_gauss_angles = 1)

A high-level RRTMGP data structure storing the optical properties, sources, boundary conditions and fluxes configurations for a non-scattering longwave simulation.

Fields

  • context: ClimaComms context.
  • op: Optical properties.
  • src: Longwave source functions.
  • bcs: Longwave boundary conditions.
  • fluxb: Temporary storage for bandwise calculations.
  • flux: Longwave fluxes.
  • angle_disc: Angular discretization; n_gauss_angles sets the number of Gauss-Jacobi-5 quadrature angles (1-4) used for the hemispheric integral of the spectral solve. One angle is the diffusivity approximation; more angles resolve the angular integral better, at proportional cost. Gray radiation is single-angle and rejects anything but 1.
  • state_cache: TransposedStateCache with column-first copies of the hot state arrays (refreshed at each spectral solve), or nothing.

G-point groups

A two-stream solve can spread its g-point loop across the threads of one wider kernel instead of running it on one thread per column. These hold the per-group workspaces that make that possible.

RRTMGP.RTE.LWGptGroups — Type
LWGptGroups(grid_params::RRTMGPGridParams, ngroups; params)

Workspaces for solving a column's longwave g-point loop in ngroups independent pieces, all in one kernel launch.

At one thread per column the solve's grid is 96 blocks of 256 threads, and the kernel's 255 registers pin it to one block per SM, so 108 SMs hold 0.89 of that grid at once. The device is already full. Splitting the g-point loop multiplies the number of blocks instead: ncol * ngroups threads is some 14 waves, and the scheduler refills an SM as each block retires, which is what absorbs the tail and the imbalance between columns. This is the restructure priced in section 4l of the profiling study.

Every workspace the solve indexes by column is widened to ncol * ngroups columns, so a thread's (column, group) pair selects its own slice by a single index and the kernel body is the ungrouped one with that index substituted for the column wherever it touches scratch. Nothing is per-group-allocated and nothing has a group axis to walk: the reduction recovers the group from the wide column index.

ngroups > 1 is implemented for CUDA. The CPU driver ignores these workspaces and solves the whole g-point loop per column, which is correct either way.

RRTMGP.RTE.SWGptGroups — Type
SWGptGroups(grid_params::RRTMGPGridParams, ngroups)

Workspaces for solving a column's shortwave g-point loop in ngroups independent pieces, all in one kernel launch.

LWGptGroups carries the reasoning, and it holds here unchanged: the shortwave solve's grid is also 96 blocks of 256 threads pinned to one block per SM by 255 registers, so 108 SMs hold 0.89 of it and the parallelism has to come from more blocks rather than from more occupancy.

Two things differ from the longwave. FluxSW carries a direct-beam profile, so a group accumulates three of them rather than two. And the shortwave sweeps only where the sun is up, so every group of a night column exits its loop at once – at fourteen waves an SM that retires such a block is handed another, which is the load imbalance section 4l of the profiling study measured as unobtainable while the grid was one wave.

RRTMGP.RTE.default_ngpt_groups — Function
default_ngpt_groups(grid_params::RRTMGPGridParams)

How many g-point groups a two-stream solver widens to when the caller names none: enough to reach TARGET_GPT_GROUP_COLUMNS wide columns, capped at MAX_NGPT_GROUPS.

A column count that already fills the device gets one group, because the grid it launches is wide enough without them and the workspaces cost memory linearly in the group count either way. Pass ngpt_groups explicitly to override this in either direction.
